# web-sales-demos
Web制作営業用デモサイト

## デモサイトURL公開ルール（固定運用）

完成済みの8セクション画像をURL公開する場合は、以下を標準手順とする。

### 役割分担
- ChatGPT：GitHub Contents APIで確認し、会社別フォルダ内に `index.html` を作成・更新し、公開URLを確認する。
- ユーザー：完成済み画像8枚を会社別フォルダへGitHub画面から一括アップロードする。
- ChatGPTは画像のアップロード、圧縮、変換、リサイズ、結合、再生成を行わない。画像の差し替えも原則ユーザーが行う。

### 画像ファイル準備
- 8枚の画像が完成した段階で、ChatGPTがGitHubアップロード用の正しい順番・ファイル名に揃えてユーザーへ渡す。
- ユーザーは受け取った画像のファイル名を変更せず、そのままGitHubへ一括アップロードする。
- ファイル名は拡張子を含めて完成形とし、Windows側で手動で `.png` を追加しない。
- `.png.png` のような拡張子の二重付与を防止する。

### CTAボタン配置ルール
- 「無料見積り」「無料相談」等の主要CTAボタンは、原則2か所に限定する。
- セクション1（ファーストビュー）に1か所、セクション8（最終お問い合わせ）に1か所配置する。
- セクション2〜7には、原則として主要CTAボタンを配置しない。
- 同じCTA文言やボタンを各セクションへ繰り返し配置しない。
- CTAを追加する場合は、明確な導線上の理由がある場合に限る。

### 標準手順
1. ChatGPTが会社別フォルダ名を決め、`<company-folder>/index.html` をContents API経由で作成する。これにより会社別フォルダも作成される。
2. `index.html` は8枚の画像を上から順に縦表示する最小構成とする。
3. 画像完成後、ChatGPTがアップロード用ファイル名に揃えて8枚を準備する。
4. ユーザーが会社別フォルダを開き、準備済みの画像8枚をファイル名を変更せず一括アップロードする。
5. 画像名は以下で統一する。
   - `01-hero.png`
   - `02-problems.png`
   - `03-about.png`
   - `04-services.png`
   - `05-reasons.png`
   - `06-reviews.png`
   - `07-lifestyle.png`
   - `08-contact.png`
6. ユーザーからアップロード完了の連絡を受けたら、ChatGPTはContents APIで8枚の存在・順番・ファイル名を確認する。
7. `.png.png` 等の命名ミスがないことも確認する。
8. 問題がなければ公開URLを確認してユーザーへ提示する。

### 修正時
- 画像内容・順番を直す場合は、原則としてユーザーが対象画像を削除・差し替えする。
- GitHub上の画像削除をユーザーから依頼された場合は、ChatGPTがContents API経由で削除してよい。
- 同じファイル名で差し替える場合、`index.html` の変更は不要。

### 禁止事項
- ChatGPT側から画像をGitHubへアップロードしようとしない。
- URL公開作業中に画像圧縮・変換・リサイズ等の別作業へ逸脱しない。
- ユーザーが画像をアップロードする前に、画像が存在すると仮定して公開完了扱いにしない。
- ユーザーに完成済み画像のファイル名を手作業で変更させる運用を標準にしない。
- 不要な再確認や品質比較を繰り返さない。

### 目標
画像完成後の公開作業は、役割分担を崩さず最短で進める。ユーザーの画像アップロード後は、Contents API確認から公開URL確認まで原則1〜2分程度で完了できる運用を目指す。
